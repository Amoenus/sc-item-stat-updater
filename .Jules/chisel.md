## 2025-05-14 - Scraper Decoupling
Learning: The `bin/scrape-scmdb.js` file functioned as a massive procedural God-class handling both raw SCMDB JSON downloading, directory setup, CSV file I/O, and complex domain mapping for missions/blueprints.
Action: Extracted all domain mapping, traversal (blueprint chain depths), and array generation (mission rows) into a distinct, typed module `src/lib/scmdb/mission-parser.js`. I/O layers must remain purely concerned with CLI args and writing to disk, relying on pure parser functions containing standard `@typedef`s to replace undocumented generic object graphs.

## 2024-05-16 - SCMDB DTO Consolidation
Learning: Found widespread duplication of generic, unstructured interface definitions matching upstream SCMDB JSON data in `mission-parser.ts` and `mining-parser.ts`. These manual types introduced the risk of `any` fields and loose typing. By exporting Zod schemas from `src/schema/scmdb.schemas.ts` and deriving strict types via `z.infer`, we ensure a single source of truth for both runtime validation and compile-time TypeScript checks, eliminating massive `any` vulnerabilities.
Action: Derived and exported explicit DTO types (e.g., `ScmdbContractDTO`, `ScmdbMiningDataDTO`) directly from `scmdb.schemas.ts` and removed the manual redundant interface definitions inside the extractor modules.

## 2024-05-17 - Extraction Logic Encapsulation
Learning: Found large duplicated procedural logic blocks across CLI scripts (`bin/scrape-scmdb.ts`, `bin/regen-mining-locations.ts`) responsible for deeply nested extraction and probability-weighted mapping of mining deposits. The scripts were also using unsafe `any`-casts for the parsed `miningData.json`. By moving all extraction, transformation, sorting, and quality-note extraction deeply inside `src/extractor/mining-parser.ts`, the CLI scripts are reduced to simply invoking `buildMiningLocationRows` with strict `ScmdbMiningDataSchema.parse()` boundaries. This solidifies the Extract/Transform boundary and guarantees output predictability.
Action: Ensured `buildMiningLocationRows` retains `.sort()` guarantees, explicitly typed internal variables without massive manual DTO repetitions, and delegated complex multi-pass iterations cleanly out of execution files.

## 2026-05-20 - Zod Schema DTO Drift in Internal Helper Signatures
Learning: `processOverrideEntries` in `mining-parser.ts` used a manually-typed inline signature `{ distribution: {...} | undefined; locations: string[] | undefined }[]` that diverged from the Zod-derived `ScmdbLocationOverrideEntrySchema` type (where both fields are `?:` optional). TypeScript strict mode treats optional (`?:`) and required-but-possibly-undefined (`T | undefined`) as incompatible, causing a TS2345 error invisible until `tsc --noEmit` was run. The inline type was a ticking drift clock — any future schema change would silently misalign.
Action: Export `ScmdbLocationOverrideEntryDTO` (via `z.infer`) from `scmdb.schemas.ts` and use it as the parameter type in `processOverrideEntries`. All internal helper signatures in extractors/parsers that consume SCMDB data must derive from exported Zod DTOs — never from manually-typed inline object literals.
