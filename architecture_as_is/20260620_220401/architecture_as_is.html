Entrypoints And Runtime

Commands

  • npm run pipeline: full flow: refresh sources, update global.ini, deploy.
  • npm run pipeline:cached: use existing source outputs, still extract/update/deploy unless flags alter behavior.
  • npm run cache, cache:datacore, cache:scmdb: refresh source outputs without updating global.ini.
  • npm run update: advanced update from existing outputs.
  • npm run extract, npm run deploy: local game localization IO utilities.
  • npm run check:architecture, npm run check:no-generated-churn, npm run typecheck, npm test: verification commands.

Apps, Services, Workers

No long-running server, web app, database process, queue consumer, or cloud worker was observed. This repository is built as local CLI tooling.

Routes, APIs, CLIs, Jobs

The public runtime surface is CLI commands. External APIs are consumed by source acquisition, especially SCMDB URLs under https://scmdb.net/data. DataCore extraction uses local game files and an unforge-style extraction callback rather than a network service.

Runtime Configuration

  • .env.example documents SC_LIVE_DIR as the local Star Citizen LIVE install directory.
  • package.json declares Node >=24.0.0 and Volta Node 24.16.0.
  • Commands use node --env-file-if-exists .env.local --import tsx/esm, so local machine env files influence runtime but are not committed.

Architecture Observations

Observed

  • The repository has an explicit clean pipeline architecture document and an automated guardrail script.
  • CLI scripts are thin adapters around presentation command modules and application use cases.
  • Patch plans are intentionally separate from INI mutation; persisted artifacts use a compact entries/issues shape.
  • Generated data is committed and guarded by a churn check, which treats csv/ and root global.ini as sensitive outputs.
  • There is no observed service deployment model; execution is local and file-oriented.

Inferred

  • The repo is mid-migration from SCMDB-dependent enrichment toward DataCore-first source ownership; diagnostics and docs keep remaining SCMDB dependency visible.
  • The most important architectural contract is not a network API but the file contracts between source cache outputs, item configs, patch plans, and INI application.
  • The dynamic category registry makes adding enrichment categories cheap but relies on filenames and directory placement as part of the contract.

Unknown

  • Whether current local .env.local points to a valid game install; values were not read or exposed.
  • Whether live DataCore extraction and deployment currently succeed on this machine.
  • Whether SCMDB live endpoints are currently reachable and compatible with the checked schemas.
  • Whether ignored local folders such as Data, Engine, repo, and dist are current, stale, or incidental.
